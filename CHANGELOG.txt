CHANGELOG

### v3.17.0 - Slow hardware is not a timeout (Jul 2026)

A healthy model that took >90s to prefill a large schema prompt was cut off
with "Request Timed Out" — the model WAS generating, just slowly. On modest
hardware, prefilling a 10k-token prompt (big schemas) legitimately takes
minutes. Slow and dead are now distinguished instead of conflated:

- **Keep-alives now flow during prefill.** Provider lines are pumped through
  a reader thread, so the backend's 15s `: keep-alive` heartbeat reaches the
  browser even while the model is silently reading the prompt (previously the
  heartbeat itself was blocked exactly when it mattered).
- **Frontend watchdogs now measure transport liveness, not model speed** —
  re-armed by any received bytes, keep-alives included. A model can prefill
  for 10 minutes without being cut off; a genuinely dead connection still
  fails in 90s, and the error now says "Connection Lost", not "Timed Out".
- **Wedged-provider guard moved to the backend**: the stream errors only
  after `LLM_STREAM_READ_TIMEOUT` of true provider silence (default 600s;
  set the env var higher for extreme hardware).
- After 45s without a first token, the status bar pins a notice ("model is
  still reading the schema…") so a long prefill doesn't look like a hang.
  The Stop button works the whole time.

### v3.16.1 - BLOB columns no longer crash uploads and queries (Jul 2026)

Uploading a real-world forensic DB (Skype) 500'd: BLOB values (avatars,
capability bitmasks, protobufs) in the rich-schema sample rows aren't JSON
serializable. The same latent bug sat in /execute_sql (any `SELECT *` over a
BLOB column) and the Row Inspector's FK lookup.

- All JSON row paths now sanitize cells via `jsonsafe_row()`: BLOBs render as
  `<BLOB 108 bytes, hex 89504e47…>` — size plus leading hex, so file
  signatures (89504e47 = PNG) stay recognizable to an examiner.
- The LLM's schema sample rows show the same placeholder instead of a noisy
  Python bytes repr, telling the model the column is binary.
- 7 new regression tests (255 total), verified against the real Skype DB.

### v3.16.0 - Honest context bar + the model finally sees its own results (Jul 2026)

Driven by a real failure transcript: valid queries kept returning 0 rows and
the model never knew — the user had to paste "no results" back by hand.

#### Context (ctx) bar now tells the truth
- **Real denominator:** the model's actual context window is fetched from the
  provider (LM Studio `/api/v0/models` `loaded_context_length`, Ollama
  `/api/show` `num_ctx`/GGUF metadata) and surfaced via `/api/provider/status`
  (60s cache). Previously hardcoded to 32k — a 108k model showed a full bar
  at a third of its capacity.
- **Real numerator:** the bar now shows the *last* turn's total tokens (the
  prompt already re-contains system + schema + history). The old cumulative
  sum double-counted every turn — in practice the bar pinned at "full" while
  real occupancy was ~5%. Per-bubble token counters keep the session total.
- Tooltip shows `used of window (last turn)`; when the provider can't report
  a window (older LM Studio builds), the bar falls back to a marked ~32k
  estimate.

#### SQL accuracy: query-outcome feedback
- **The model now sees what its queries returned.** Prior turns carry a
  compact `[Query outcome: N rows returned]` note (the most recent also gets
  a ≤3-row preview, safely fenced as untrusted data). An empty result is no
  longer invisible: ask "why did that return nothing?" and the model knows.
  Context only — never an auto-retry; "no rows" can be the forensically
  correct answer.
- **Prompt hardening for local models:** positive capability note (CTEs,
  window functions), SQLite's silent bare-column-in-aggregate trap, type
  affinity (`IS NULL`, TEXT-stored dates/numbers), and explicit guidance to
  treat 0-row outcomes as evidence rather than guessing variations.
- **INTEGER enum grounding:** value annotations now cover low-cardinality
  INTEGER columns (message direction, status codes — ubiquitous in forensic
  DBs), numerically sorted, primary keys skipped.
- **Mis-fenced SQL still executes:** the frontend now accepts untagged fences
  and bare SELECT/WITH/EXPLAIN/PRAGMA responses (matching the backend's
  tolerant extraction); weak models that forget the ```sql tag no longer
  produce silent no-ops. Server-side validation unchanged.

### v3.15.0 - Senior-dev sweep: trust fixes, resilience, release hardening (Jul 2026)

Full-project audit pass (backend, frontend, distribution) before wrap-up.
Theme: a forensic tool must never silently misrepresent results.

#### Trust & correctness
- **Row-cap truncation is now visible:** results capped at 2,000 rows return a
  `truncated` flag; the UI shows a warning banner ("only the first 2,000 rows
  are shown"), the row-count label and CSV tooltip say so, and truncated CSV
  exports are named `query_results_TRUNCATED.csv`. Previously a 50k-row match
  displayed "2000 rows returned" with no hint more existed.
- **A streamed answer can no longer be destroyed by bookkeeping:** if the
  session-save call fails after a successful stream, the answer stays rendered
  and its SQL still executes (previously the whole reply was replaced by an
  error bubble).
- **Partial answers survive disconnects:** if the provider dies or stalls
  mid-stream, the text streamed so far is kept with a "connection interrupted /
  stream stalled" note — same contract as the Stop button (SQL from truncated
  responses is never executed). A new inter-token idle watchdog (120s) means a
  wedged provider can't leave the composer stuck on Stop forever.
- **Search All Tables fixed and bounded:** `%`/`_` in a search term no longer
  act as SQL wildcards (terms match literally); the GLOB branch whose `*?[`
  metacharacters corrupted case-sensitive searches is gone; per-column scans
  are capped (200 values) with a "counts are lower bounds" note on huge DBs —
  previously a common term on a multi-GB database could hang the server.
- **`.sql` uploads: no more keyword false-positives:** a table named
  `attachments` no longer trips the ATTACH blocklist (word-boundary matching
  on string/comment-stripped SQL).
- **CSV uploads: colliding headers survive:** `Order ID` + `Order-ID` used to
  fail the whole conversion with "duplicate column name"; sanitized duplicates
  now get numeric suffixes.
- **Read-only connections actually close** on exit (sqlite3's context manager
  only ends the transaction) — no more lingering Windows file handles that
  could collide with Replace DB.
- **Leading `/* block comments */` no longer reject valid SQL** in the
  validator (line comments already worked).

#### UX & polish
- **Clear stored data:** new Storage section in settings — deletes stored
  upload copies (except the currently loaded DB) and stale session files,
  after a confirm dialog; reports files removed and MB freed.
- Footer timing/row metrics reset when a new question is sent or the DB is
  replaced (no more stale "1,432 rows" under an unrelated answer).
- Minimized welcome screen leaves the keyboard tab order (was an invisible
  focus trap); long FK names ellipsize in the Row Inspector; the "leave page?"
  prompt only fires when there's an actual conversation.
- Error responses no longer echo raw exception text (paths, sqlite internals)
  to the client; malformed Row Inspector requests get a clean 400; the log
  file now truly rotates daily (30 days kept).
- Rapid-send edge: a superseded stream's late cleanup can no longer clobber
  the new stream's composer state or status shimmer; sub-2.5s responses keep
  the shimmer's anti-flash minimum display.

#### Distribution & CI
- CI now tests on **Windows and Ubuntu** (Windows is a primary install target
  with its own code paths and was previously untested).
- New **wheel packaging smoke test**: CI builds the wheel, installs it in a
  clean venv, and verifies the app serves its templates/static assets —
  editable-mode tests can't catch a wheel that ships without data files.
  The publish workflow runs the same check before uploading to PyPI, and now
  fails fast if the git tag doesn't match the pyproject version.
- `--host 0.0.0.0` no longer auto-opens the unloadable `http://0.0.0.0:...`
  (opens loopback instead); a busy port prints a friendly "try --port N"
  message instead of a traceback.
- README: version badge is now the live PyPI badge (can't drift again); the
  Ollama example model is a real tag (`gemma3:27b`, was the nonexistent
  `gemma4:26b`). run.bat enforces the same Python 3.10+ minimum as the
  installers.
- 24 new tests (219 total): SSE streaming path, CSV/.sql upload branches,
  truncation flag, search caps, clear-stored-data, service-worker versioning.

### v3.14.0 - SQL accuracy: execution-feedback loop + value grounding (Jul 2026)

Research-driven pass at the query error rate. Both changes follow the
text-to-SQL literature: correction works when the model sees real execution
errors, and hallucinated WHERE-clause values disappear when the model is shown
the values that actually exist.

#### New / Changed
- **Multi-round auto-correction:** a failed query now gets up to two correction
  rounds (was one), each fed the latest SQLite error. Previously tried queries
  are listed in the prompt so the model doesn't resubmit them; a repeated
  suggestion ends the loop early. Correction prompts now include sample rows,
  fixing wrong date-format and value assumptions.
- **Value grounding:** enum-like TEXT columns (≤12 distinct values, ≤40 chars,
  tables ≤50k rows) get their real values listed in the schema context
  ("-- values of messages.direction: 'MSG_RCV', 'MSG_SENT'"), inside the
  untrusted-data markers. The system prompt instructs the model to copy listed
  values exactly. Under context-budget pressure the annotations are the first
  thing dropped, before sample rows.
- **README:** new "Choosing a model" note — SQL-specialized local models
  (e.g. Arctic-Text2SQL-R1-7B GGUF) are worth A/B-testing on SQL-heavy sessions.

Note: prompts are larger — grounding and feedback trade tokens for accuracy.
Schema context stays capped by the existing budget and degrades gracefully.

### v3.12.0 - Reliability, security, and CI sweep (Jul 2026)

Full-project audit pass: lower query error rates with local models, patched
vendored libraries, cross-site request hardening, and a CI test gate in
front of PyPI publishing.

#### New / Changed
- **SQLite-specific prompt rules:** the system prompt now teaches the model the
  pitfalls that caused most failed queries — double-quoted identifiers (never
  backticks), strftime/date/datetime instead of DATE_FORMAT/NOW, `||` instead
  of CONCAT, LIKE's ASCII case-insensitivity, and exact schema-name copying.
- **Tolerant SQL extraction:** the client and the retry fallback now accept
  ```SQL / ```sqlite tags, single-line fences, untagged fences (retry only),
  and bare-SQL responses, instead of requiring a perfectly formatted lowercase
  ```sql block. Everything extracted still passes validate_sql().
- **Consistent auto-correction instructions:** the retry previously told the
  model to return JSON (system message) *and* a ```sql block (user prompt) at
  the same time; both now ask for the same JSON shape the grammar constraint
  enforces. New targeted hints for "ambiguous column", "misuse of aggregate",
  and "no such function" errors.
- **Gradual schema-budget degradation:** on budget overflow, sample rows are
  reduced to 1 per table before being dropped entirely — sample values are the
  model's strongest signal for real column contents.
- **CI:** new GitHub Actions test workflow (Python 3.10 + 3.13, plus ruff
  lint) on every push/PR; the PyPI publish workflow now requires tests to pass
  before building — a v* tag can no longer ship a broken release.
- **Tests:** 125 → 172 (database.py was previously untested, including the
  .sql import security gate; plus extraction, budget-ladder, prompt, and
  cross-site guard tests).

#### Security
- **DOMPurify 3.0.8 → 3.4.11:** closes published sanitizer-bypass CVEs
  (CVE-2024-45801/47875, CVE-2025-26791, CVE-2026-0540). DOMPurify is the XSS
  boundary for all LLM-rendered markdown. Highlight.js 11.9.0 → 11.11.1.
  Vendored library versions are now recorded in static/lib/VERSIONS.md.
- **Per-install session secret:** the hardcoded dev fallback key is gone; a
  random key is generated once and persisted in the user data dir
  (SECRET_KEY env var still takes precedence).
- **Cross-site POST guard:** SameSite=Lax session cookie plus Origin/Host
  validation on POST routes — a malicious web page can no longer fire
  CSRF/DNS-rebinding requests at localhost:5000.
- **No internal error leakage:** the global exception handler returns a
  generic message; details go to the log only.

#### Fixed
- **LM Studio broken on current builds:** recent LM Studio versions return
  400 Bad Request when the request omits the model id (older builds ignored
  it). The loaded chat model is now resolved via /v1/models at call time —
  mirroring the Ollama pattern — and included in the payload; embedding
  models are skipped. Old LM Studio builds keep working (field omitted when
  unresolvable).
- **Reasoning models returned empty auto-corrections:** LM Studio can leave a
  reasoning model's final answer in reasoning_content with an empty content
  field; the SQL-correction retry now falls back to it. Verified live against
  qwen3.6-27b: misspelled-column queries are auto-corrected again.
- **Timeout message said "15 seconds"** while the actual watchdog is 90 s.
- **Keyboard accessibility:** schema-browser table rows and Row Inspector
  foreign-key links are now focusable and operable with Enter/Space.
- Removed dead code (vestigial sidebar toggle, unused CSS reader); deduplicated
  the Windows file-lock retry loops and the welcome-screen minimize logic.
- README version badge was two minor versions stale; mis-filed "Unreleased"
  CHANGELOG block merged into its actual release (v3.10.0).

### v3.11.1 - Streaming and security hardening follow-up (Jun 2026)

#### Fixed
- **SSE stream not completing on server drop (LM Studio):** If the HTTP connection
  closed before the `data: [DONE]` sentinel arrived (server crash, model OOM), the
  frontend received no `event: done` frame and always showed a timeout error — even
  for complete responses. A post-loop fallback now emits `event: done` whenever the
  stream closes without a terminal signal.
- **Generator continued after `event: done` (both providers):** Neither the Ollama
  nor the LM Studio branch broke out of the `iter_lines()` loop after emitting the
  done frame. Trailing bytes or a second `done: true` line could produce spurious
  post-done `event: token` frames (silently dropped by the client) or a duplicate
  done frame. Both branches now `break` immediately after emitting done.
- **Injection fence bypassable via crafted cell values:** A database row whose value
  was exactly `<<END_UNTRUSTED_DATA>>` (≤ 50 chars, within the truncation limit)
  would be emitted as a bare line indistinguishable from the real fence-closing
  marker, potentially exposing subsequent row values as trusted model context. All
  sample cell values and column names now have `<<` replaced with `««` before
  insertion into the prompt.
- **Schema budget bypass for very wide DDL:** After dropping sample rows on budget
  overflow, the DDL-only schema was returned without a second size check. A database
  with thousands of tables could still produce a DDL-only context exceeding the
  20 000-char budget, silently overflowing the model's context window. The fallback
  now hard-truncates with a visible `[...schema truncated]` marker if DDL alone
  still exceeds the limit.
- **AbortController watchdog cleared by keepalive comment:** The 90-second stream
  watchdog was disarmed on the first raw `reader.read()` result, which includes SSE
  keepalive comment frames (`: keep-alive`). A model that emitted one keepalive and
  then stalled indefinitely would clear the watchdog before generating any content,
  leaving the UI spinner running forever. The watchdog is now cleared only on the
  first real named event (`token`, `done`, or `error`).
- **SSE `parseFrame` discarded all but the last `data:` line:** Multiple `data:`
  lines in one SSE frame (valid per WHATWG spec) were overwritten instead of
  concatenated with `\n`. Now correctly concatenated.
- **O(n²) streaming render:** `renderText` (full `marked.parse` + `DOMPurify` +
  `innerHTML`) was called on every `event: token` frame with the full accumulated
  response string, making total rendering work quadratic in response length. All
  streaming renders are now gated behind `requestAnimationFrame` so multiple tokens
  arriving within a single animation frame are batched into one DOM update.

### v3.11.0 - Backend hardening: SSE streaming, prompt security, schema budget (Jun 2026)

#### Changed
- **Proper SSE streaming:** The `/chat_stream` endpoint now emits a real
  `text/event-stream` response with named SSE events (`event: token`,
  `event: done`, `event: error`) instead of the previous in-band magic-string
  sentinel (`<|END_OF_STREAM|>`). The full response is no longer re-sent at
  stream end — the frontend accumulates it from token events, cutting payload
  size in half for long answers. Periodic `: keep-alive` comments prevent
  proxy idle-timeout drops during slow local-model generation.
- **Prompt injection fencing:** Sample rows injected into the LLM system prompt
  are now wrapped in explicit `<<UNTRUSTED_DATA>>` / `<<END_UNTRUSTED_DATA>>`
  markers with a corresponding system-prompt rule instructing the model to treat
  that content as data values only, never as instructions. Defense-in-depth for
  adversarial forensic databases where cell values may contain injected text.
- **Schema-context token budget:** `build_schema_context()` now enforces a
  20,000-character soft budget (~5k tokens). When a wide database exceeds it,
  sample rows are dropped automatically and a visible notice is prepended
  (`[NOTE: Large schema — sample rows omitted…]`) so the LLM understands why
  samples are absent. The `schema_truncated` flag is also included in the
  `/upload` response for future UI use. Prevents silent context-window overflow
  on local models with smaller context windows.

#### Tests
- 24 new test cases (101 → 125 total): SSE frame format for both Ollama and
  LM Studio providers, error/timeout frame format, confirmation that full
  response is never re-sent in the done frame, untrusted-data marker presence,
  schema budget trigger, system-prompt untrusted-data rule.

### v3.10.1 - Windows installer fix (Jun 2026)

#### Fixed
- **Windows installer false-failure on pipx bootstrap (round 2):** `Invoke-Native` piped
  the wrapped command's stdout directly into the function's output stream, so a *successful*
  `pip install pipx` caused the caller's `$rc` to be an array of stdout strings + exit code.
  `if ($rc -ne 0)` on an array is a PS filter (truthy even on success), so the installer
  reported "pip exited Collecting pipx … Successfully installed … 0" and aborted even though
  pipx had been installed correctly. Stdout is now routed via `Out-Host` so it stays visible
  to the user but does not pollute the return value; `$rc` is always a clean integer.

### v3.10.0 - Backend inference & reliability improvements (Jun 2026)

#### New / Changed
- **Reproducible results:** LLM temperature lowered to 0 with a fixed seed so the same
  question produces the same SQL for a fixed model and runtime — useful for forensic
  reproducibility notes. (Results may differ if the model file or server version changes.)
- **Model warmth (Ollama):** `keep_alive: 30m` added to every Ollama request. The model
  stays loaded across a forensic session instead of unloading after the default 5-minute
  idle, eliminating cold-reload stalls mid-investigation.
- **Response cap on retry:** the SQL auto-correction retry path caps output at 2048 tokens
  (`max_tokens` / `num_predict`). The main streaming chat is uncapped so long explanations
  and complex multi-CTE queries are never silently truncated.
- **Smarter auto-correction:** the SQL retry path now requests a constrained JSON response
  `{"sql": "..."}` from the provider (grammar-constrained generation), with the old
  markdown regex as a belt-and-suspenders fallback. Eliminates silent failures when the
  model formats its answer differently.
- **No hardcoded model name:** `OLLAMA_MODEL` default removed. Ollama now auto-selects the
  first installed model when no session pick or `OLLAMA_MODEL` env var is set — the
  codebase no longer contains a model name that can go stale.
- **Read-only consistency:** `build_schema_context()` now opens a proper read-only
  connection instead of a regular `sqlite3.connect()`, matching the app's read-only
  promise end-to-end.

#### Fixed
- **False "Request Timed Out" errors:** the frontend watchdog was 15 seconds, too short
  for local models to prefill a large forensic schema before the first token. Raised to
  90 seconds — the watchdog clears on the first token so normal short responses are
  unaffected.
- **Stale Ollama error hint:** "ollama pull llama3.2" replaced with "ollama list" so
  users aren't instructed to pull a specific model that may not suit their hardware.
- **Redundant search re-filtering:** case-sensitive table search now relies entirely on
  SQLite's GLOB (which is already case-sensitive) and skips the redundant Python
  re-filter pass.
- **Windows installer** (`install.ps1`): Script incorrectly reported "Could not
  install pipx" on clean machines even though pip exited 0. Root cause: PS 5.1
  wraps native-command stderr into ErrorRecords when `2>&1` is used, which trips
  `$ErrorActionPreference = "Stop"` regardless of exit code. Harmless pip
  warnings (e.g. PATH notice) were terminating the script. Fix: judge all
  native-command success by `$LASTEXITCODE`, never by stderr capture; use
  `python -m pipx install` (module form) as the primary install path so the
  script works even when `pipx.exe` isn't on the session PATH yet.

### Earlier History (v1.1–v3.2)

Versions 3.0–3.2 explored packaging as a native desktop app via pywebview and PyInstaller. That approach was superseded by the browser-first PWA architecture in v3.3. The desktop-specific build scripts, fixes, and workarounds from those versions have been removed.

Key milestones from the pre-PWA era:

- **v3.2** — LLM pipeline overhaul: richer schema context (DDL + foreign keys + sample rows), decision framework for SQL vs plain-language answers, few-shot examples in system prompt
- **v3.1** — SQL auto-retry on error, enriched schema with column types and constraints, security hardening (14 bare `except:` fixes, quoted PRAGMA table names), ARIA accessibility on modals, favicon
- **v3.0** — Version display endpoint, LLM connection guidance in sidebar, refresh button with confirmation modal
- **v2.5** — Dual LLM provider support (LM Studio + Ollama) with status polling, dynamic model selection, XSS prevention in exports and search
- **v2.4** — Custom confirmation/alert modals with focus management
- **v2.2** — Digital Forensics Terminal theme (JetBrains Mono, amber/cyan palette, scan-line effects, slide-in animations)
- **v2.0** — Dark/light theme toggle, Search All Tables, 12 forensic SQL functions (removed in v3.5.0), multi-column sorting
- **v1.7** — CTE (WITH clause) support, EXPLAIN/PRAGMA support, database-level read-only enforcement (`mode=ro` + `query_only`)
- **v1.6** — Grid.js interactive tables, forensic annotations on messages, syntax highlighting
- **v1.5** — Drag-and-drop file upload, persistent welcome banner
- **v1.4** — SHA256 evidence hashing, audit logging, forensic export headers, CSV/SQL file import, file validation, backend timeouts
- **v1.2** — Token usage tracking with hover breakdown
- **v1.1** — Chat export styling, upload confirmation dialogs
